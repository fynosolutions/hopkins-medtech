# AI review 工作流设计：通用流程与 Hopkins 首个样板

日期：2026-10-10（Asia/Shanghai）｜状态：第一步设计，待毛审阅；尚未执行样板、编写运行脚本或形成公司通过结论。

依据：[Issue #12](https://github.com/fynosolutions/hopkins-medtech/issues/12)，核对版本 `updatedAt=2026-10-10T05:33:19Z`，包含 7 个设计问题、10 项必含要求、三件套 13 个组成部分及 5 项工作流要求。**内部原文待补充核对**：尚未收到“验资前审核流程”原文，也未核对两次通话原始记录；本设计落实的是 Issue 已列出的要求，不声称完成与内部流程的对照。

## 一页决策摘要：回答 Issue 的 7 个问题

目标：在事实有依据的前提下，发现公司对外材料的缺口、矛盾及 AI 误读，给网站、LinkedIn、资料包负责人可执行的修复任务。AI 的“真实”判断是测试结果，不是公司真实性或实习安全的证明。

**主流程：接收三件套与事实清单 → 冻结版本、资料包机检 → 13 项逐件审核与跨件对表 → 仅依据资料的组合问答 → 独立评分、人工复核 → 分配整改 → 受影响范围复测 → 毛决定材料能否对外使用。** 收录后另跑无资料的可见度测试；索引是否开放由毛单独决定。

| Issue 问题 | 执行答案 |
|---|---|
| 1. 同一天能闭环吗？ | 能完成第一层的“检查 → 改材料 → 复测”，不依赖收录。以固定资料投喂为主，网址读取为辅助诊断；资料或平台缺失时先交诊断报告，完整验收保持未完成。见 A、C、H。 |
| 2. 两层如何分、通过标准是多少？ | 第一层只用给定材料检验内容，第二层不给资料、网址或标准答案，检验自主发现。分别出表、逐引擎验收；沿用 0–3 分规则，七类信任问法判真实比例 ≥90%，核心 0 分阻断，发送前任何 0 分、未复核红旗、未备齐证据均阻断；不以平均分替代。见 C、D。 |
| 3. 能否自动化、需要什么、成本多少？ | API 自动收集/评分与产品端人工实测并行设计。OpenAI、Gemini、Perplexity 均研究了现行联网接口，需要对应 API 账号、密钥和计费；API 不冒充产品端。含审核追问及评分，示例第一层自动诊断约 $4.48；两层自动测试及全部人工回答的机器评分约 $16.08，预留后建议 $25/公司/完整初测，人工另计。见 F。 |
| 4. 怎样自动评分且防裁判编造？ | 负责人确认的事实清单作为真值基准，当前官网快照作为公开表达基准；独立模型逐断言匹配证据，规则程序核对引用、字段、阈值，人工复核所有红旗和未确认事实。裁判不联网补答案，无证据不下真假结论。见 A、D。 |
| 5. 如何换公司复用？ | 固定流程、题型、判分、报告、适配器；更换公司配置、材料、事实清单、负责人及特色问题。通用模板使用公司变量，Hopkins 原始中文问题单独锁定。样板获准并跑通后才落成 `ai-review/` 工具包。见 G。 |
| 6. 结果怎样转成改站任务？ | 每条 AI 批评都关联“原文 → 缺失/矛盾/漏读/检索等原因 → 具体材料位置 → 有来源的必需内容或需要负责人提供 → 负责人 → 优先级 → 复测项”。网站项可贴进 #1 的 PR，LinkedIn/PDF 项交对应负责人。见 E。 |
| 7. 新公司半天出报告可行吗？ | 工具就绪、材料可读取时，目标 4 小时内出诊断报告；缺证据、登录限制、全量人工操作会阻碍完整验收，不承诺半天获准发送。首次开发/校准单独估算 2–3 个工作日，需第二步授权。见 H。 |

**发送前最后一关：** 无 0 分项、无任何引擎对公司作出“骗局”判断、每条回答前 6 句无经复核的负面判断、13 项审核与跨件一致性通过、人员 LinkedIn 截图/注册证明/实习条款可立即提供、外发材料无未核实内容，最后由毛点头。只要必要测试或事实待补，就不标通过。第一层放行材料不代表第二层已通过，更不代表获准开放索引。

**已与用户讨论并确认的口径（2026-10-10）：** 负面关键词保留全部命中并按语义复核；事实待确认或平台测试缺失时可先交诊断报告，完整验收保持未完成；内部原文待补充核对。以上细则提交毛审阅，不把用户对设计口径的确认当作毛对样板执行、公司事实或外发材料的批准。

## A. 输入、事实依据与资料包机检

### A1. 接收与冻结

运行前登记 `company_id、run_id、trigger、scope、owner、started_at、next_retest_date`；触发原因包括新公司接入、准备外发、某页/PDF/LinkedIn 改动、模型或规则变化、收录后复测。收齐或逐项标缺：官网页面、LinkedIn 公司/帖子/个人主页、整合 PDF、岗位 PDF、中介介绍包，以及负责人确认的事实清单与证明材料。

每份材料保存原文、URL/文件名、主体、获取时间、版本、内容哈希、页码/段落定位与可用截图；网页读取受限时由负责人提供文字版和截图，并注明“提供材料”，不伪称抓取成功。旧版保留不覆盖。锁定题库、提示词、裁判规则、模型及运行条件，改任一项都产生新版本。

事实清单每条包含：`fact_id、field、value、subject、source_url/证据位置、原文摘录、confirmed_by、confirmed_at、status、可否公开、关联组件`。字段覆盖公司品牌名/法定名称、地址、业务、团队及职位、岗位与招聘状态、官方链接、邮箱、实习条款、合作/资质主体。状态为已确认、待确认或存在冲突；空值不推断，资料与证据不一致先查证。

裁判可以看到事实清单和已确认的证据；被测模型只能看到该测试条件允许的公开材料，不能收到裁判答案、分数目标或“请认为这是真公司”等诱导。官网当前文字用于判断是否有公开依据，但网页重复某个说法不等于该说法已经核实。

### A2. 两个核心文件及介绍包

- **整合 PDF（英文）**：公司介绍、官网和 LinkedIn 的文字版、来源网址、必要截图、团队、实习安排、申请渠道及全部岗位的职责/产出摘要。让家长只拖这一个文件，就能回答已核实范围内的主要问题；截图不能替代正文。缺项必须如实说明，不做虚假完整性承诺。
- **岗位 PDF（英文、独立更新）**：逐岗位完整说明、职责、产出、条件及已确认条款；稳定岗位 ID、岗位数量、版本和更新日期。整合 PDF 保留对应岗位摘要及所依赖的岗位 PDF 版本；岗位变动后摘要也受影响，不能只换附件而保留矛盾内容。
- **中介介绍包（中英双语）**：明确受众痛点、公司怎样解决、可交付内容和证据；中英文事实一致，不增加未经证实的合作或效果保证。它是第三类资料，不替代前两个核心文件。

机检设计：检查文件能否打开且无提取限制；逐正文页可提取文字，无乱码/空正文；核对标题、法定名称等必需字段以及每个岗位 ID/职责/产出是否在提取结果中；核对网址、截图说明、文件版本/日期、岗位数量和三处字段；抽查 PDF 原页面与提取文字，不能把 OCR 推测直接当事实。

体积采用**项目暂定软限值**：每个核心 PDF ≤5 MB、两个核心文件合计提取正文 ≤20,000 tokens；这不是任何厂商的官方上限。运行前按目标平台实际限制和首次读取探测调整，超限先压缩图片/去重复装饰，不删事实和出处、不静默截断；仍过大就报告限制。任何局部阅读的诊断都标明范围，不能作为完整文件通过证据。保存上传耗时、提取耗时、是否超时及首尾/各章节读取检查结果，重点检查豆包的大文件表现。

### A3. Hopkins 的事实边界

遵守仓库 `AGENTS.md`：不推断 HMC 与约翰霍普金斯大学的关联，也不写肯定或否定关联声明；该题回答完整交毛。公司登记号尚未确认，登记信息缺口只能列“需要负责人提供”。Jeff Wu 仅使用已确认的 Co-founder 和本人 LinkedIn 链接，不补履历、职务或照片。8 个岗位的工作方式限已确认的 Remote / Onsite，不写仍接受申请、首次发布日期、具体地址、远程国家或全远程。

“检查是否在招/是否有证书、推荐信/FDA 记录”是审核要求，不是这些事实已成立。逐项要求来源，不适用需负责人确认理由；不能填一个不存在的资质来凑齐表。HML、DiaCarta 等主体的资质不得转写为 HMC 自有资质。未确认项阻止相关完整验收，但不阻止出诊断报告。

## B. 三件套审核范围：13 项、跨件对表与整体审核

### B1. 逐项审核表

每一行都必须独立输出 `通过 / 缺什么 / 与哪一件不一致`，并附证据定位、分数或待核原因、负责人。允许缺失与不一致同时存在，未提供的材料不记通过。集合项逐成员、逐帖子、逐岗位出子结果，父项不能只抽样通过。

| ID | 组件 | 必查内容及可读出的答案 | 整改责任 |
|---|---|---|---|
| W1 | 官网首页 | 一句话说清公司是谁、业务、法定名称；品牌名与实体名的对应有依据 | 网站负责人；实体事实由毛确认 |
| W2 | 官网团队页 | 每人的职位、LinkedIn 链接，与本人及公司页一致；不编造员工/经历 | 网站负责人；本人核实 |
| W3 | 官网招聘页及 8 个岗位 | 每个岗位的真实性证据、职责、产出和稳定 ID；招聘状态单独核实 | 招聘及网站负责人 |
| W4 | 官网实习项目页 | 带教、节奏、协议、证书、推荐信、申请渠道逐项是否明确且有依据 | 项目及网站负责人 |
| W5 | 官网资质与公开记录 | 注册信息、FDA 记录、合作公告逐条可追溯；证据的主体/日期/适用范围正确 | 毛/业务负责人；网站负责人 |
| W6 | 官网隐私与条款 | 页面存在、可读，表单/申请/个人数据处理等描述与实际一致 | 业务及网站负责人 |
| L1 | LinkedIn 公司页 | About 前两句、实体、地址、行业标签与官网一致 | 公司页负责人 |
| L2 | LinkedIn 专业深度帖 | 审核清单内每帖与业务一致，具体事实追到一手来源；锁定帖子清单，不能挑选有利帖子 | 内容负责人 |
| L3 | LinkedIn 岗位帖 | 每帖招聘人确属雇主、岗位真实在招且有确认时间；与 W3、D2 对应 | 招聘及公司页负责人 |
| L4 | 核心人物个人主页 | 当前职位挂公司、头衔与官网一致，身份有依据；只能本人改，我们只核对 | 本人；协调负责人 |
| D1 | 英文整合 PDF | 官网/LinkedIn 文字版、网址、截图齐全；可选中文字，单文件能覆盖家长问题 | 资料包负责人 |
| D2 | 英文岗位 PDF | 岗位增减后数量、版本、日期及正文同步，与官网各岗位一致 | 招聘及资料包负责人 |
| D3 | 中英双语中介介绍包 | 痛点→解决办法，双方语言事实一致，无无据合作和承诺 | 中介材料负责人 |

### B2. 跨件对表

生成“字段 × 材料”表：法定名称、地址、人员头衔、岗位数、联系邮箱，必要时加实习条款及申请渠道。列出各处原文、标准化值、事实编号和定位，比较官网↔LinkedIn、官网↔PDF、LinkedIn↔PDF，以及 D1↔D2↔D3。只规范大小写/空格等形式差异；不同主体、地址类型、头衔和岗位状态不得强行合并。

不一致即红旗；两处都缺失仍是缺口。某字段本来不属于某组件的职责范围可以记不适用，但需说明范围，不能把首页法定名称等必查字段绕过去。旧截图与当前文字冲突也记红旗。证据只证明对应主体与对应日期的事实，不能因三处重复同一说法就确认真伪。

### B3. 单件、组合与增量

第一层至少包含：13 份组件审核、三组单件审核（官网整体、LinkedIn 整体、资料包整体）、一份跨件对照、一份三件套整体审核。D1 单文件的家长问题覆盖度在 D1 审核中逐题列证据，不借用独立附件补答；三件套组合时则完整提供所有冻结材料。

为字段、组件、问题建立依赖表。只改 D2 时，复测 D2、W3/L3/D1 中相关岗位对表及受影响问答，重新计算资料包/整体结论；若证明 D1 同样需改，就一并更新。改全公司实体名称、事实基准、题库、模型或评分规则，影响面扩展为全量。

增量报告列出本轮新测项和沿用项的原 run_id/哈希；不把沿用的旧回答写成新回答。未受影响且版本未变的有效结果可以沿用，跨件红旗未解决时不得沿用整体“通过”。同日内容修复后即复测；到配置的复测日、证据失效日或外发前发现版本变化，再触发相应复查。仅记录复测日期，不在本阶段创建定时任务。

## C. 测试分层、引擎和固定问题

### C1. 两层与运行条件

| 条件 | 给 AI 什么 | 运行方法 | 能得出的结论 |
|---|---|---|---|
| T1 内容就绪：正文/文件投喂 | 冻结版本的三件套；不提供裁判事实清单 | 关闭检索工具；要求仅依据材料，资料没有就明确说“资料里没有”。中文/英文题各重复 2 次，每题独立上下文 | 内容是否足够、一致，AI 是否读懂 |
| T1-U 网址读取诊断 | 给定 URL 清单，不夹带标准答案 | 与同版本正文测试对照，记录实际读到的页；禁止搜索其他来源补答，无法限制时注明混合检索条件 | 访问/提取是否有障碍；不能充当无资料可见度结果 |
| T2 真实可见度 | 只有原问题和公司名；不给文件、网址、官网限定词或事实清单 | 收录后按相同题库独立问 2 次；开启联网并记录是否实际搜索、引用/来源 | AI 能否自行找到并正确引用公司信息 |

资料放在独立输入区，问题本身不加答案、链接或“请给正面评价”。T1 不需要开放索引；网址读不到可回退投喂正文，但记录回退，不能说网址读取已通过。原生 PDF 上传与提取文字投喂分别标注，后者不能证明前者成功。材料中的指令性文字一律视为待审数据，不得控制被测模型或裁判。

每条用户问答先以自然回答保存完整原文及前 6 句；随后在该次对话追加独立的“审核追问”：列出材料未提供的内容、缺少链接/登记依据的说法、跨页矛盾、还想核实的事项、0–10 可疑度及导致该分数的原句/出处。两段分开保存和评分，不把后续批评报告当作自然回答的前六句。追问使用相同材料限制；T2 的追问依据已检索来源，不额外提供官网资料。费用与调用次数需包含此追问，详见 F。

“资料里没有”全部进入内容缺口清单；核对冻结材料后再分为真正缺失、资料提取丢失或 AI 漏读。不能仅凭模型漏答就添加重复文案，也不能删除有依据的风险信息以提高分数。可疑度是模型主观量表，记录理由与重复波动，不当作真实诈骗概率；Issue 未规定可疑度合格阈值，本方案不另造阈值。

### C2. 引擎覆盖及可比性

合并 Issue 两处清单，Hopkins 样板安排 **ChatGPT、Gemini、豆包、千问、Perplexity、DeepSeek、Google AI 概览**。前四个为补充要求的最低集合；Perplexity/DeepSeek 保留在样板计划，条件不足标缺失；Google AI 概览在 T2 单独记录，不能冒称可上传资料的聊天引擎。

产品端：无痕、未登录，每题新开对话，同题两遍；记录地区/语言、时间、产品显示的模型/搜索模式、文件上传方式和登录状态。遇到登录/验证码/上传限制，记“测试缺失”，不规避限制或偷偷换成登录态；经毛另行确认的替代条件单独出表，不自动抵扣缺失。没有 AI 概览时保存实际页面及普通结果，标“未出现概览”，不拿 Gemini API 或普通搜索摘要替代。

API：同题、相同资料快照、独立请求、每题两遍，记录模型 ID/版本、搜索开关、实际调用与完整响应。请求失败重试最多 2 次、退避，保留所有尝试；两次有效重复与错误重试分别编号。正常回答不因分数低而重试挑优，模型替换必须新开实验组。输入超上下文或输出被截断属于不完整记录，保留原始返回并调高预算/修正配置后重测，不截去后半段冒称完整回答；费用表中的 token 数只是估算，不是允许丢失内容的上限。

产品端与 API 分表；不同引擎、语言、测试层、输入方式都分组，不混成一个分数。Issue 中的引擎引用倾向作为待验证观察，逐次统计实际官网/LinkedIn/第三方引用，不预设某引擎一定依赖某来源。

## D. 自动评分、通过线与人工关口

### D1. 原始 0–3 分与证据标签

| 分数 | 按 Issue 的判分 | 实施约束 |
|---|---|---|
| 3 | 答对且引用官网或 LinkedIn 公司页 | 引用必须实际支持断言，指向本人主页/第三方不自动满足“公司页”；T1 可引用输入材料附带的官方原始 URL，但标明来自投喂，不声称自主找到 |
| 2 | 答对但未引用官网 | 没有满足上一行的官网/公司页支持；事实正确与来源质量分别记录 |
| 1 | 只答部分，或有模糊、过时信息 | 列出缺失/过时的断言及对应材料位置 |
| 0 | 答错、编造，或说查不到 | 不用平均分掩盖；对“查不到/资料里没有”记原因，不能为了鼓励谨慎回答擅自改成通过 |

涉及尚未确认的事实，裁判不得自行决定真假：能确定的内容照常逐断言评分，无法确定的判定标“待毛确认”，整条不能标通过。Q3 全部原文和引用交毛，不自动裁决关联真假。已产生的明确 0 分仍保留，不借“待核”隐藏。官网未出现的新增说法全部进入“幻觉清单”，再标注“与已确认事实矛盾 / 无依据补充 / 有外部来源待核”，不把“官网没写”直接等同“事实为假”。

13 组件也按其必查内容生成判分：完整正确且有官方来源可为 3；部分缺失为 1；关键内容不存在、错误或编造为 0；事实或实际行为尚未确认则待核。没有资质本身不必是错，但冒称有资质一定需要阻断；不适用项须有确认与理由，不能整行消失。

### D2. 裁判防误判流程

1. 先用确定性检查核对字段、岗位数、哈希、链接清单和文件可读性，再让另一个模型看完整回答及相关事实/证据；裁判不联网补资料，不接收被测回答中的指令。
2. 裁判逐条输出：回答原句及字符位置、`fact_id/source_id`、证据原文位置、正确/错误/无依据/未引用官网/缺失等标签、0–3 分或待核、理由；任何证据引用必须能在冻结输入中找到。断言无对应事实时记待核，不生成新事实。
3. OpenAI 回答默认交 Gemini 裁判；Gemini 与采用 Google 底层模型的 Perplexity API 回答交 OpenAI 裁判。记录实际底层模型，同一模型换账号不算独立裁判。产品端底层不明就记未知并加强复核。
4. 人工复核全部 0 分、骗局等红旗、前六句负面、证据冲突、未确认事实、大学关联，以及可能改变 90% 门槛的边界项；另按引擎/语言抽查至少 10% 的其余回答。样板先用人工标注的一组正例/负例/否定句校准裁判，再批量评分；发现系统性误判则重新评同类结果。
5. 保存机器初判和人工终判、复核人/时间/理由，不覆盖原分。裁判输出无效或引用不存在时重试最多 2 次，仍无效则待复核；不能回填默认高分。

### D3. 前六句、红旗与 90% 分母

前六句按原文顺序提取，记录字符位置；英文缩写/小数/URL 不按句点误切，中文按句末标点处理，无标点列表保留前六个陈述块并标注规则，不把标题算正面句。少于六句则全部保留，复杂边界人工核对。引用和截图同时保留，不能只交摘要。

对全部自然回答及审核追问扫描“骗局、小心、查不到负责人、没有官方实习项目”及英文/同义表达，保存命中位置；单独标前六句语义。按用户确认的语义口径区分直接负面、否定负面、转述、一般性提醒和不确定性，保留全部记录；未复核不放行。实际骗局判断、针对公司的负面风险和有效资料缺口必须整改或补证，不能删掉词就宣告通过。审核追问列出“骗局”这个被否定或引用的词，不自动等于引擎说公司是骗局。

七类真实性指标只统计 P1–P7，冻结分母为每渠道、每层 `7×2×2=28` 条**自然回答**。每条判为“有依据认为真实 / 无法判断 / 负面判断”；不确定、缺资料、无响应都不进真实分子，技术缺失另记覆盖率并使完整验收未完成。不能把没有负面词直接算真实。通过至少 `26/28≈92.9%`；同时中文和英文各至少 `13/14`，展示七类各自结果，不能删掉低分问题或合并各引擎凑比例。统计自动批量实验与产品端真实体验各自的比例，不互相抵扣。

### D4. 分层验收与外发

- **T1 内容就绪通过**：13 项及子项、必查字段、一致性、PDF 机检完成，无待核核心事实/未解决冲突；各已要求渠道 P 组达到上述比例，Q1–Q9 与 13 组件等核心项无 0 分，所有语义红旗完成人工处理。T1-U 不可读须记录原因；投喂通过不能伪称网址通过。
- **T2 可见度通过**：独立满足真实性比例与核心无 0 分、无未处理红旗、所需渠道覆盖完整；另要求各渠道 Q1–Q9 的 36 条回答中至少 90% 为 3 分，即 ≥33/36，表明答对并引用官方信息。这个官方引用阈值是本方案提交毛审批的量化建议，不冒称 Issue 原有数值。未出现 Google AI 概览不能记通过。T2 不因 T1 分数高而通过。
- **外发前最终关口**：本次拟外发材料对应的 T1 全部验收回答无 0 分，任何引擎都没有经复核的骗局判断，每条自然回答前六句无负面；13 组件与对表无未结红旗；已请求的人员 LinkedIn 截图、注册证明、实习条款有受控存放位置且能立即出示；材料无未核实内容；毛记录对版本的最终同意。若 T2 已执行，其未解决红旗/0 分也必须呈报，不得隐瞒。
- **三种独立状态**：诊断报告已出 / 内容与外发验收 / 自然搜索可见度。T2 尚未进入收录条件时明确标未测，不让它阻塞当天内容整改，也不标整个任务全部通过。`SITE_INDEXABLE` 继续关闭，除非毛另行明确批准；发布材料的同意与开放索引的同意分别记录。

| OpenAI `gpt-4.1-mini` | $0.40 / $1.60 | `web_search` $0.01/次，搜索内容按每次固定 8,000 输入 token 收费 [O2]、[O3] |
| Gemini `gemini-2.5-flash` | $0.30 / $2.50（输出包括 thinking） | 保守按超免费额后的 $0.035/grounded prompt；不能混用 Gemini 3 的计价单位 [G2] |
| Perplexity Agent / `google/gemini-3.1-flash-lite` | $0.25 / $1.50 | 标准搜索 $0.0025/次，抓 URL $0.0005/次；实际模型/工具调用数留档 [P2]、[P3] |

公式：`总费用 = Σ(输入 token × 输入单价 + 输出/思考 token × 输出单价)/1,000,000 + 工具费 + 裁判费 + 重试与诊断预留`。材料每次重新提供的 token 计费，不能把一次准备资料误算成只付一次输入费。

**以下是基准问答及审核的估算底数，随后单列审核追问和预留，不是实测账单：** 每服务 T1 为 64 次自然问答 + 18 次审核（13 组件 + 3 单件 + 1 跨件 + 1 整体），共 82 次；每次暂按 12,000 输入/1,500 输出 token。三个 API 共 246 次，费用 $1.62。T2 每服务 64 次，共 192 次，每次暂按总输入 2,000/输出 1,500 token，OpenAI 的 8,000 搜索内容另计，Gemini 每次一个 grounded prompt，Perplexity 每次一次标准搜索和一次抓取；费用 $3.94。任何额外检索轮次按实际计费。

裁判每条按 6,000 输入/600 输出 token，使用两种独立裁判中较高的单次费率 $0.00336 估算。六个聊天产品的 T1 人工回答 384 条，T2 含 Google AI 概览为 448 条；两层共 832 条，人工操作本身不算 API 问答费，机器评分另计。以上基准：T1 自动诊断加裁判 $2.45；加 T1 全部人工回答评分 $3.74；两层全部基准回答/审核和评分 $9.83。

**审核追问必须计费：** 每条自然问答还有一条 C1 审核追问，API 两层共 384 次。按 T1 每次 14,000 输入/1,500 输出，T2 每次 4,000 输入/1,500 输出且沿用已取回资料、不追加搜索估算，约 $2.17；加追问裁判（API 384 + 产品端 832）约 $4.09。两层完整估算因此约 **$16.08，预留 50% 后取整为 $25/公司/完整初测**。T1 自动诊断连追问及其评分约 **$4.48，预留后约 $7**；含 T1 全部人工回答与追问评分约 **$7.06，预留后取整为 $12**。文件更长、截断续答、二次检索和分歧复核可能增加费用，运行前按实际 token 重算。

建议单公司第一层预算上限 $12、两层合计 $25；达 80% 提醒，预估下一请求会越限就暂停发新请求、保留未完成项，不自动充值或削减必测问题。选择这些模型仅为可复算初始方案，不宣称最优；第二步先用小样本校准质量/费用，模型变化重新记录与估价。当天修复按依赖范围复测，按受影响次数追加预算，不默认整轮重跑。

## G. 复用结构与后续实施范围

本阶段仅提交本 Markdown 设计和 Issue 要点。毛确认设计后，第二步才实施 Hopkins 样板；样板跑通后第三步整理下列结构，当前不创建空脚本冒充完成：

```text
ai-review/
  README.md                  # 一页操作说明、前置条件、费用和状态解释
  templates/                 # 问题、事实清单、材料清单、整改/报告模板
  rules/                     # 评分、前六句、红旗、依赖关系、阈值
  adapters/                  # API 与人工记录导入的统一接口
  scripts/                   # 机检、运行、评分、报告、增量复测
  companies/<company-id>/    # 公司配置、特色问题、材料索引；敏感事实私有存放
qa/ai-review/YYYY-MM-DD.md    # 获准后的原始记录入口，未授权不推送公开仓库
```

固定项：流程与阶段、题型/中英模板、评分/红旗规则、13 组件类别、运行及报告格式。每公司替换项：公司名/实体及别名、官方域名/LinkedIn、事实/材料/证据、岗位与人员清单、负责人、特色问题、地区语言和复测日期。账号按服务配置，不与某公司硬编码绑定。通过替换配置运行，不需改评分程序；任何特殊放行条件必须显式记录，不能私自降低门槛。

接口固定输出上述记录字段，以便后续接入更多引擎。新公司先验证配置完整性，拒绝遗留 Hopkins 名称、网址或事实；换公司仍需负责人提供和确认事实，不能靠改公司名生成标准答案。

## H. 时间、交付与当前待补事项

### H1. 新公司四小时诊断目标

在工具已可用、公司资料可读取的前提下安排：0–30 分钟登记/冻结/事实缺口；30–60 分钟机检/13 项与一致性；60–150 分钟 API 问答、追问、评分及可用产品端探测；150–210 分钟人工核对红旗/关键证据、分派整改；210–240 分钟整理报告并复测少量已完成修复。耗时是工作估算，不是已验证 SLA；补资料、复杂修复、平台排队与毛的确认可能跨日。

单人手工跑 T1 全部六个产品，仅自然问答就 384 次；若每次操作/等待/保存平均 1–2 分钟，约 6.4–12.8 小时，另有追问和复核。不能宣称靠 API 就完成了这些产品端测试。半天先交覆盖状态清楚的诊断报告，剩余人工项继续排期；完整验收必须补齐，或由毛明确修订范围并留下决定，不能因超时默默缩题/少测引擎。

首次搭建、API 冒烟、记录导入、评分校准及报告打通，初步估算 2–3 个工作日，不计为每家公司的四小时运行时长；本阶段不启动这些工作。若要所有人工产品端全量测试也在半天内完成，需要另行安排操作人力/合规自动采集能力，不能在未验证前承诺。
